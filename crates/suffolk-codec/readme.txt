================================================================================
 suffolk-codec (Suffolk Codec / Serializer & Deserializer)
================================================================================

【このクレートの役割】
中間表現（`suffolk-ir` の `DocumentIR`）と、外部の翻訳データ交換フォーマット
（CATツール標準の XLIFF や、Shuttle 独自の JSON など）との「相互変換（エンコード／デコード）」
を担当するクレートです。

【なぜ独立しているのか】
「原稿（WordやExcel）の解析」と「翻訳データの保存・交換フォーマット」は全く別の関心事です。
例えば、将来 XLIFF 2.0 に対応したり、別ツールの JSON スキーマに対応する際にも、
ファイルパーサー（formats）に手を加えることなく、この codec クレートの修正だけで
対応できるように分離されています。

【配置されているロジック・ファイル構成】
- src/
  ├─ lib.rs
  │    モジュールの公開設定および主要な型・関数の再エクスポート。
  │
  ├─ xliff.rs
  │    翻訳業界のデファクトスタンダードである XLIFF 1.2 (XML) のパーサーおよびジェネレーター。
  │    ・`write_xliff_12()`: DocumentIR から .xlf / .xliff ファイルを生成
  │    ・`parse_xliff_12()`: 翻訳済みの XLIFF ファイルを読み込み、訳文を抽出
  │    quick-xml を用いた高速かつ安全なストリーミング処理を実装しています。
  │
  ├─ shwv.rs
  │    Shuttle Web Viewer（JSONをSSOTとする翻訳支援Webツール）のネイティブフォーマット
  │    `ShWvData` との相互変換ロジック。
  │    ・DocumentIR から Shuttle 形式 JSON を生成
  │    ・Shuttle 形式 JSON から翻訳済みのテキスト・セグメントを逆抽出
  │
  └─ failsafe.rs
       万が一の緊急時（CATツールや独自JSONが読めなくなった場合など）のための
       フェイルセーフ用エクスポート機能。プレーンテキスト（.txt）や CSV 形式で
       翻訳対象セグメントを素早く書き出します。

【依存関係】
・参照元（依存しているクレート）: `suffolk-ir`
・外部ライブラリ: serde, serde_json, quick-xml, csv, thiserror
