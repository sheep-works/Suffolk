================================================================================
 suffolk-ir (Suffolk Intermediate Representation)
================================================================================

【このクレートの役割】
Suffolk のすべての処理の基盤となる「中間表現（IR: Intermediate Representation）」の
データ型定義と、テキスト解析（文分割、タグ抽出）を行うコアクレートです。
他のクレート（formats, codec, cli）が共通して依存する最下層に位置します。

【なぜ独立しているのか】
DOCX や HTML などの様々な原稿形式、および XLIFF や JSON などの様々な出力形式が
お互いに直接依存しあうと、コードが複雑化（スパゲッティ化）し循環参照が発生します。
共通のデータ構造（中間表現）を一元管理することで、新しいファイル形式の追加や
出力形式の追加が簡単に行える設計になっています。

【配置されているロジック・ファイル構成】
- src/
  ├─ lib.rs
  │    モジュールの公開設定（外部から利用しやすいように各型を re-export）。
  │
  ├─ model.rs
  │    中間表現のデータモデル構造体群を定義しています。
  │    ・DocumentIR: 1つのファイル全体のメタ情報と翻訳単位をまとめた親構造体
  │    ・DocumentMeta: 元ファイル名、言語コード(src/trg)、フォーマット種別、文字コード等
  │    ・UnitIR: パラグラフやブロック単位の翻訳単位
  │    ・SegmentIR: 1文ごとの原文（source）と訳文（target）
  │    ・TagIR: 書式タグ（太字、斜体、リンクなど）のインライン情報
  │
  ├─ segmenter.rs
  │    テキストを文（センテンス）単位に分割するロジックです。
  │    句読点（。や.）だけでなく、省略形（Mr., Dr., etc.）、引用符（「」、“”）、
  │    括弧、改行、数字の小数点を考慮した高精度な境界判定を行います。
  │
  └─ placeholders.rs
       XML/HTML などの複雑な書式タグを、翻訳者が扱いやすい `<1>`, `</1>` のような
       番号付きプレースホルダー（抽象タグ）に抽出・復元するロジックです。

【依存関係】
・Suffolk 内の他クレートには一切依存していません。
・外部ライブラリ: serde（シリアライズ）, regex（正規表現）, thiserror（エラー処理）
================================================================================
